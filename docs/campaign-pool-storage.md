# Campaign item pool storage (1.10.0)

Owlbear room metadata is limited to less than 16 KB total across extensions and all their keys: https://docs.owlbear.rodeo/extensions/apis/room/. Previous versions put every pool definition into that budget alongside the public combat log. A large scan could reject the entire write. The error was shown behind the modal while the modal reported an empty pool. Earlier mocks did not enforce the room limit.

The pool now uses namespaced scene metadata. Characters and combat data retain their existing schema and token ownership. The browser stores a separate backup for each Owlbear room. On scene change/open the GM's backup is merged into the new scene and shared with GMs using that scene. Legacy room entries are read and merged without deleting them or other extensions' data. Definitions are still capped at 2000; browser snapshots and JSON imports are capped at 4 MB. Timestamps and tombstones prevent deleted definitions from being restored by older scenes or caches.

The pool reads fresh scene items from the SDK when scanning. Opening or refreshing reconstructs definitions from the characters on the map; a malformed item is reported without preventing other entries from being recovered. Sharing/write failures appear inside the pool, while available definitions remain backed up locally for export/retry. A browser backup failure is also shown explicitly. The refresh icon retries scanning and sharing.

Scene storage and browser backup are not a global account database. A GM on a different device gets the current scene's shared catalog, but a separate room or an otherwise empty scene on a fresh browser needs a library import. Save to account opens Owlbear's folder picker and creates an Odyssey Item Pool scene snapshot with blueprint metadata on text items. Load from account opens the scene picker and merges selected pool snapshots; it does not open a game scene. This uses the same official Assets API flow as character templates: https://docs.owlbear.rodeo/extensions/apis/assets/. The UI does not claim that closing the save picker confirms a successful upload. JSON export/import remains available.

Regression tests enforce the real 16 KB room limit and reproduce the previous empty-pool behaviour using the old controller. They verify a larger scene catalog with a nearly full room, character switching, loss of original tokens, reload and new-scene restoration, a second GM without local storage, account snapshot restore, fresh SDK item recovery, deletion tombstones and visible/recoverable write errors. No external database or automatic connection is introduced.
